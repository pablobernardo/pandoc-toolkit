# i18n del CLI — estrategia y guía de contribución

Esta guía define cómo internacionalizar mensajes del toolkit sin romper el contrato del CLI, manteniendo seguridad y testabilidad.

## Objetivo

- Soportar múltiples idiomas para mensajes del CLI y scripts de runtime.
- Hacer trivial agregar un nuevo idioma.
- Mantener estabilidad en códigos de salida, flags y semántica de comandos.

## Principios

1. **Contrato estable del CLI**: i18n no cambia exit codes ni estructura de comandos.
2. **Catálogo por claves**: nunca hardcodear textos nuevos en runtime.
3. **Seguridad por defecto**: locale resuelto contra catálogos soportados del toolkit, sin carga dinámica de rutas arbitrarias.
4. **Paridad de placeholders** entre idiomas.

## Resolución de idioma

Orden recomendado:

1. `PANDOC_PDF_LANG` (explícito)
2. config global del toolkit (`~/.config/pandoc-pdf/config.env`)
3. `LC_ALL` / `LANG`
4. fallback de proyecto (inicialmente `en`)

Comandos de soporte en CLI:

- `pandoc-pdf locale show` — muestra idioma efectivo y fuente.
- `pandoc-pdf locale set <lang>` — guarda idioma global por usuario.
- `pandoc-pdf locale set --project <lang>` — guarda idioma por proyecto en `.pandoc-pdf.env`.

Normalización recomendada:

- aceptar `es`, `en`, `pt-BR` (BCP-47)
- para resolución interna, mapear a locales soportados (ej.: `es-AR` -> `es`)

## Estructura recomendada

```text
i18n/
  locales/
    en.json
    es.json
    pt.json
    gl.json
  schema/
    messages.schema.json
```

Formato de catálogo (ejemplo):

```json
{
  "cli.error.unknown_command": "Comando desconocido: {command}",
  "doctor.ok": "Doctor OK: dependencias disponibles"
}
```

## Secciones de documentación por código de idioma

Para la guía técnica de i18n, usar un único documento (`docs/i18n.md`) con secciones por locale:

- `## Locale: es`
- `## Locale: en`
- `## Cómo agregar un locale nuevo`

Para documentación de usuario final, mantener una única versión hasta necesitar localización completa. Cuando sea necesario, migrar a árbol dedicado:

```text
docs/es/
docs/en/
```

## Cómo agregar un nuevo idioma

Checklist de PR:

1. Crear `i18n/locales/<locale>.json`.
2. Copiar todas las claves base del locale de referencia.
3. Traducir valores sin alterar claves.
4. Verificar paridad de placeholders (`{name}`, `{path}`, etc.).
5. Añadir/actualizar tests de cobertura de catálogo.
6. Validar smoke tests del CLI con `PANDOC_PDF_LANG=<locale>`.
7. Documentar locale en esta guía.

## Estrategia de tests

Mínimos obligatorios:

1. **Completeness**: todos los locales tienen las mismas claves.
2. **Placeholder parity**: placeholders idénticos por clave entre locales.
3. **Locale policy**: locales inválidos no cargan catálogos externos.
4. **Fallback**: locale no soportado cae al idioma por defecto.
5. **Smoke CLI**: mensajes representativos en locales activos (`en`, `es`, `pt`, `gl`).

## Requisitos de seguridad

1. No construir rutas de catálogo desde input no validado.
2. Resolver locale únicamente contra catálogo soportado del toolkit.
3. No usar `eval` ni templates ejecutables para interpolación.
4. Cargar catálogos con parser seguro y validación de esquema.
5. Limitar tamaño razonable de catálogos para evitar abuso.
