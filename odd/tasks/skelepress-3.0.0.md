Branch: `feat/skelepress-3.0.0`; delivery: one major release, `auto-chain` / `feature-branch-chain`; runner: `make gate`. #164 holds the decisions; this document is the execution spec.
Scope: the rename plus the explicitly approved book output-root default in S10. No schema shape or pipeline change. Clean break: no shim, no aliases, no dual config loading.

## Specs

- S1: The command is `skelepress`. The repository, the workflow titles, the skill, the release assets and the managed layout use the same name. #164, verbatim: "le llamamos skelepress".
- S2: The conventional/generated configuration file is `skelepress.config.yaml`, and the schema is `schemas/skelepress-config.schema.json`. `pdf.config.yaml` is **not** an alias or fallback: there is one consumer, the maintainer, who deletes the old files by hand. Preserve S6: the existing CLI requires explicit `--config` and accepts arbitrary paths, so a user-supplied basename is not a validation rule.
- S3: The environment variables are `SKELEPRESS_*`. All 17 `PANDOC_PDF_*` names are renamed, and nothing reads both.
- S4: No compatibility path exists: no `pandoc-pdf` shim, no variable aliases, no fallback filename. The 3.0.0 changelog states the break and the absence of a migration path — #164, verbatim: "lo de la guia de migración da un poco igual porque solo lo estoy usando yo".
- S5: `AGENTS.md` is amended so the breaking-change policy requires a migration guide **when the change reaches a consumer other than the maintainer**. Until it is amended, the policy contradicts the release.
- S6: Nothing else changes except the explicitly approved default in S10: same commands, same flags, same messages (except names and that default inside them), same schema shape, same output bytes for equivalent input and output paths, same `VERSION` scheme and tag convention.
- S7: The rename is verified mechanically, not by eye: after the change, `git grep -i 'pandoc-pdf\|PANDOC_PDF'` returns nothing outside the changelog history, notes that record the old name, and tests proving the old names are rejected; `make gate` is green.

## Risks that this release must answer

- **The published releases keep their asset names.** `v2.5.2` and earlier publish `pandoc-pdf_*`. The old updater hardcodes that asset family and cannot upgrade to a release containing only `skelepress_*`. Under the approved clean break, acceptance proves rejection leaves the old installation unchanged, then verifies a clean 3.0.0 installation. Do not add duplicate assets, aliases or adoption logic.
- **An existing installation at the old managed root** `~/.local/share/pandoc-pdf` stays there. The maintainer removes it by hand; nothing detects or migrates it, and nothing may silently write to the new root while the old binary is still on `PATH`.
- **The repository rename on GitHub** keeps a redirect, so old clones keep working, but every `https://github.com/pablobernardo/pandoc-toolkit/...` URL in the docs must be rewritten in the same change.
- **The suite is the safety net.** 570 tests reference the command; if the rename is applied inconsistently, the gate fails loudly. Do not silence failures by relaxing assertions.
