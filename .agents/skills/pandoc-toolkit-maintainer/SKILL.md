## When to use

- When a change affects the contract (`schemas/pdf-config.schema.json` or the
  structure of `pdf.config.yaml`).
- When render, preflight or configuration validation is modified.
- When touching integration tests, the CI pipeline, or usage and migration
  documentation.

## Critical patterns

1. **Contract first, implementation second**
   - If config or schema changes: update the schema and fixtures first, then the
     CLI and scripts, then the docs.

2. **Mandatory synchronisation**
   - If functional behaviour changes, update in the same task:
     - tests (`tests/run.sh` plus the area files under `tests/l1/`),
     - documentation (`README.md`, `docs/usage.md`, `docs/migration.md`),
     - context and state (`CONTEXT.md` when it applies).

3. **Minimum output validation**
   - Always run `tests/run.sh` before closing.
   - If integration or CI changes, propose running L2 or L3.

4. **No legacy debt**
   - Do not reintroduce legacy scripts or coupled paths.
   - Keep paths declarative and resolved against `project.base_dir`.

5. **One language**
   - The repository is English, including this file and `CONTEXT.md`; the only
     Spanish in the tree is `i18n/locales/es.json`.

## Operating checklist

- [ ] Change classified: contract, implementation, tests, docs, CI.
- [ ] Fixtures and tests updated for the new behaviour.
- [ ] `tests/run.sh` green.
- [ ] Documentation aligned with the real state.
- [ ] No references to removed paths or legacy scripts.

## Quick decision table

| If you change... | You must also touch... |
| --- | --- |
| `schemas/pdf-config.schema.json` | `tests/fixtures/*`, the validate tests, `docs/usage.md` |
| `scripts/render-native.py` | the render tests under `tests/l1/render.sh`, render fixtures, `docs/usage.md` |
| `scripts/preflight.py` or `scripts/validate-config.py` | doctor and validate tests, `docs/usage.md` |
| `.github/workflows/ci.yml` | `README.md`, `docs/usage.md` |
| the base template (`templates/`) | `examples/`, affected fixtures, docs |

## Commands

```bash
pandoc-pdf doctor
pandoc-pdf validate-config -c examples/pdf.config.example.yaml
tests/run.sh
```
