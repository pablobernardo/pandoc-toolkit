# Book example

A proof-of-concept book laid out with the public `pandoc-pdf` CLI: front
matter with roman numerals, numbered chapters and lettered appendices,
typeset through a dedicated `book` LaTeX template.

```bash
bash build.sh
```

The build runs from any working directory and writes the PDF to
`../.output/book/` (gitignored).

## What this example proves

- A book is **content plus a manifest**: `manifest.yaml` lists what the book
  contains (front matter, chapters, back matter, in reading order) and says
  nothing about how it is rendered. There is no engine, template or filter
  setting in it.
- The toolkit needs a **declarative `pdf.config.yaml`**, not a manifest. The
  bridge is `build.sh`, a small glue step that reads the manifest and writes
  the configuration, then calls `pandoc-pdf render`. The toolkit itself does
  not know manifests exist.
- `input.explicit_files` carries the reading order (front matter first, then
  chapters, then appendices), so the merge order is exactly the manifest
  order. Every listed file must exist: the renderer fails loudly on a missing
  path, which is why the manifest contains no placeholders.

## Why the glue lives here and not in the toolkit

The manifest is a book-shaped convenience, not a contract. Making the toolkit
understand it would add a second configuration format to maintain and version.
Instead, each consuming project keeps a tiny generator step next to its
content; the toolkit stays a stable CLI plus one configuration schema, and the
glue can be rewritten in any language without touching the toolkit.

## How the mode markers work

The LaTeX `book` class structures a volume with three mode commands, and the
example uses raw LaTeX at the top of the content files to trigger them:

- The **template** opens the front matter with `\frontmatter`, so the table of
  contents and the front files share one continuous roman sequence. Front files
  therefore carry no marker of their own; the dedication still suppresses its
  folio with `\thispagestyle{empty}`, as dedications conventionally do, and a
  page that needs no number simply does not print one.
- The **first chapter** opens with `\mainmatter`: back to arabic page numbers
  and numbered `\chapter` headings. Only the first chapter carries it;
  re-issuing it would restart the numbering of every chapter.
- The **first back-matter** file opens with `\appendix`: from there, chapter
  numbers print as letters (`A Glossary`, `B About the Author`). `\appendix`
  was chosen over `\backmatter` because `\backmatter` turns chapter numbering
  off entirely, and this example wants visibly lettered appendices.

Raw LaTeX in the Markdown source is the mechanism: pandoc passes those
commands through to the LaTeX output untouched. The consequence is that this
example is **PDF-only** — the same raw commands would be dropped by an EPUB
render, so the generated configuration declares only `formats: [pdf]`.

The page break between chapters comes from two sources: the renderer inserts
`\clearpage` before each file that starts with an `# H1`, and `\chapter`
issues its own break. The document class is `openany`, and the template
redefines `\frontmatter` and `\mainmatter` to respect it (TeX Live 2026's
`book.cls` calls `\cleardoublepage` unconditionally in both, which would
insert blank pages); the result is a compact book with no blank versos.

## Files

- `manifest.yaml` — content-only manifest (title, author, ordered file lists).
- `content/front/`, `content/chapters/`, `content/back/` — the book itself.
- `templates/book.tex` — example `book`-class template; not the toolkit
  default and without the default template's D14 symbol fallback.
- `build.sh` — the glue: manifest to `pdf.config.yaml` to `pandoc-pdf render`.
- `pdf.config.yaml` — generated by `build.sh`; edit `manifest.yaml`, not this.
